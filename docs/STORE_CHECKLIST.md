# Store readiness

State of the build against what iOS and Android actually require. "Done" means
present in this repository and verified.

## Done

- **App icon** - `assets/icon.png`, 1024x1024, opaque (iOS rejects
  transparency in the store icon). Generated by `npm run assets`, so it is
  editable code rather than an unversioned blob.
- **Android adaptive icon** - `assets/adaptive-icon.png` foreground plus
  `adaptive-icon-monochrome.png` for themed icons, both inset to survive the
  circular mask, on a `#0B1B2B` background.
- **Splash** - `assets/splash-icon.png` wired through the
  `expo-splash-screen` plugin with matching light and dark backgrounds.
- **Notification icon** - `assets/notification-icon.png`, a white silhouette
  for Android to tint, with a `rank-drop` channel declared.
- **Favicon** - `assets/favicon.png` for the web build.
- **`app.json`** - name, slug, `game.closer.app` on both platforms, portrait
  lock, dark UI style, `newArchEnabled`, `edgeToEdgeEnabled`, explicit Android
  permissions (`POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM`),
  `ITSAppUsesNonExemptEncryption: false` so the export-compliance question does
  not block every submission, and an `appVersion` runtime version policy for
  updates.
- **`eas.json`** - development, preview and production profiles with channels,
  `appVersionSource: remote`, `autoIncrement` on production, app-bundle output
  for Play and a submit profile skeleton.
- **State persistence** - attempts, ratings and results survive the app being
  killed. This was the one gap that made the game unshippable rather than
  unpolished: without it a player could restart mid-set and get a second run at
  the same seven questions.
- **Notification permission flow** - requested at the moment it makes sense
  (after a set is submitted) rather than on first launch, and re-offerable from
  the profile screen.
- **Content** - 77 questions, 11 days of unique content, every answer verified
  inside its own range by a test, every question carrying a source and a
  `verifiedAt` date. Repeat protection cycles the whole bank before anything
  reappears, including across the cycle seam.
- **Accessibility** - the slider exposes an adjustable role with increment and
  decrement actions, the rank-drop cinematic honours reduced motion, and every
  interactive element has a role and a label.

## Needed before submission

These require an account, a legal page or a device - none can be finished from
the repository alone.

1. **Apple Developer Program membership and a Google Play developer account.**
2. **An Expo project id.** `eas init` registers the project and writes
   `extra.eas.projectId`. It is deliberately absent rather than filled with a
   placeholder UUID, which would fail at build time in a more confusing way.
3. **`eas update:configure`** to populate the updates URL, now that the runtime
   version policy is set.
4. **Real submit credentials** in `eas.json` - `appleId`, `ascAppId`,
   `appleTeamId`, and a Play service-account JSON that must not be committed.
5. **A privacy policy and terms page.** `app.json` points `extra.privacyPolicyUrl`
   and `extra.termsUrl` at `https://closer.game/...`; those pages have to exist,
   and the URL has to be entered in App Store Connect and Play Console.
6. **App Privacy / Data safety answers.** Currently truthful answers are
   straightforward: no accounts, no tracking, no data leaves the device. That
   changes the moment the backend lands, and both stores treat a stale
   declaration as a violation.
7. **Store listing assets** - screenshots at the required sizes for each
   device class, a description, keywords, and an age rating questionnaire.
8. **A device pass on the real build.** The web bundle is verified end to end,
   but haptics, notification delivery, the safe-area insets on a notched device
   and the share sheet are all platform behaviour that a browser cannot prove.

## Known gaps that are not blockers

- **No account.** Progress is device-local. Shippable, but it should be said
  plainly in the listing as well as in the app, or the first one-star review
  writes itself.
- **A simulated field.** Placements are generated from a per-day seed. Fine for
  a soft launch; misleading the moment the app claims real global competition.
- **No friends graph.** `RankResult.friendsPosition` is seeded, and the share
  card has no deep link back into the app yet - which is the acquisition loop
  the format depends on.
- **Content runway.** 11 days is enough to launch and not enough to retain.
  Sustaining a year needs roughly 2,500 questions, which is an editorial
  pipeline, not a code change.
